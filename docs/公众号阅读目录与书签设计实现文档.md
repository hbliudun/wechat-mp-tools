# 公众号阅读目录与书签 设计实现文档

## 1. 问题

公众号默认按时间流排列，博主自己不分类。用户看一个 2023 年的系列，读到第 10 篇，
下次想接着看，只能从最新一篇一页页往回翻。原项目里：

- 「文章下载」页的列表是**实时从微信读书上游拉取**的，每翻一页都请求上游，越翻越容易触发风控；
- 「下载历史」页只覆盖**已下载到本地**的文章，且阅读位置只存在内存里，刷新即丢失；
- 数据层没有已读、书签、阅读位置任一字段。

## 2. 目标

1. 目录是**本地的**：翻页、搜索、按年份浏览不再打上游；
2. 能记录**我看到哪了**：已读状态 + 「上次读到」+ 一键继续阅读；
3. 能**插书签**，并汇总成跨公众号的待读清单；
4. 阅读状态是用户数据，任何同步都不能覆盖它。

## 3. 数据设计

两类文件，职责严格分开：

| 文件 | 性质 | 内容 |
|---|---|---|
| `data/article_index/<fakeid>.json` | **可重建缓存** | 文章列表（标题/链接/封面/摘要/作者/发布时间/key）、`complete` 是否扫到尽头、`pages_done`、`built_at` |
| `data/reading_state.json` | **用户数据** | `accounts.<fakeid>.articles.<key> = {read, read_at, bookmark, bookmark_at}` 与 `last_read` |

分开的原因：目录随时可重新同步，丢了不心疼；已读/书签丢了是真实损失。所以同步只写索引，
读状态永远单独读写。

### 文章主键

```python
def article_key(article):
    rid = article["id"]            # 上游 reviewId
    if rid: return f"rid:{rid}"
    if link: return "url:" + md5(link)[:16]
    return "tt:" + md5(title + publish_time)[:16]
```

同一篇文章在不同次同步、不同入口下必须得到同一个 key，否则已读标记会「错位」。

## 4. 后端 `backend/reading.py`

蓝图 `/api/reading`，10 个路由：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/overview` | 每个公众号的进度：总数/已读/未读/书签/上次读到 |
| GET | `/index?fakeid=` | 某公众号完整目录 + 状态合并结果 + 年份汇总 |
| POST | `/mark` | 单篇已读/书签；`read=true` 时顺带更新「上次读到」 |
| POST | `/mark-batch` | 批量标记（如「整年标已读」） |
| POST | `/last-read` | 只更新阅读位置，不改已读状态 |
| GET | `/bookmarks` | 跨公众号书签清单 |
| POST | `/reset` | 清空阅读状态，保留索引 |
| POST | `/sync` | 启动后台同步，返回 `task_id` |
| GET | `/sync-status/<task_id>` | 轮询进度 |
| POST | `/sync-cancel/<task_id>` | 停止同步 |

`fakeid` 一律用查询参数/请求体传递，**不放进路径**：它可能是含 `+ / =` 的 Base64，
放进 URL 路径会被拆坏。

### 同步策略

复用 `backend/articles.py::_fetch_articles_page()`（含 401 续期、-2014 退避、-2041 会话激活、
防水墙检测），逐页扫描：

- `full=true`：从头扫到无更多文章，补齐更早的历史，成功则把索引标记为完整；
- `full=false`（默认）：**增量**，整页文章都已在索引里就停 —— 日常「有没有更新」只需翻一页；
- 每页之间温和节流；检测到防水墙立即停止并回报原因，不硬闯；
- 页码上限 500 页兜底，避免误操作把上游扫穿。

合并时用 `key` 去重、更新已有条目的字段，最后按发布时间倒序（时间未知的置顶推文排最前）。

## 5. 前端 `frontend/js/components/reading.js`

路由 `#reading`，左右两栏：

- **左栏**：公众号卡片，带阅读进度条、「已读 x/y · 📌 n」、「上次读到：《…》」；
- **右栏**：工具栏（即时搜索 / 全部 / 未读 / 已读 / 📌书签 / 增量更新 / 全量重建）+ 目录；
- **目录**：按年份分组、年份可折叠、每个年份可「整年标已读/未读」，行内有已读勾选、书签、复制链接；
- **继续阅读**：顶部按钮滚动定位到 `last_read` 那一篇并闪烁高亮；切换公众号时自动定位。

要点：

- 列表一次性取回，筛选和搜索都在前端做，输入即时生效，不发请求；
- 标记操作用乐观更新（先改 UI 再发请求，失败回滚），点击无延迟；
- UI 状态（选中公众号、折叠年份、筛选、搜索词）存 `localStorage`，刷新后回到原位；
- 文章 key 通过 `data-key` 传递并走 `closest('.reading-article').dataset.key`，
  **不拼进内联 JS 字符串** —— 含引号的 reviewId 会被 HTML 实体解码后破坏脚本；
- 「下载历史」页头部新增「📖 阅读目录」，按当前筛选的公众号跳转（那边只有昵称，
  阅读目录用 `_fakeidForName()` 反查 fakeid）。

## 6. 验证

- `backend/reading.py`：桩掉 flask 与上游分页，覆盖 key 稳定性、同步合并、增量不覆盖状态、
  标记/批量标记、书签汇总、年份汇总、状态文件落盘格式；
- HTTP 层：真实 Flask `test_client()` 跑全部 10 个路由，含 Base64 fakeid 走查询参数、
  同步后台任务 start → status → 目录并入；
- 前端：Node + `vm` 加载组件，覆盖 render 结构、四种筛选、搜索、年份分组、折叠、
  HTML 转义、`data-key` 传递、统计刷新、UI 状态持久化、空态。

## 7. 已知边界

- 目录完整性受上游分页深度限制：微信读书对单个公众号的回溯深度有限，
  `complete=false` 时界面会标注「目录尚未完整」；
- 阅读状态按 `fakeid` 存，公众号改名不影响，但换 fakeid 会变成新账号；
- 仅覆盖「已加入目录」的文章；未同步过的公众号需要先点一次同步。
